04Test every ending

The Test Table on your handout has two parts. Every ending proves each ending can be reached. Boundary tests check each inequality right at its cutoff and one step past it, because that’s where off-by-one bugs hide. This lab runs the exemplar’s Test Table for you.

Lab: run the exemplar’s Test Table

Change only one input at a time. Look at the boundary rows: each pair is identical except for one number. If the ending changes, you know exactly which comparison caused it.

08Make it yours

  
Your story should be your own: different setting, different questions, different endings. These hints are about the process, so open one when you’re stuck.

  
Hint 1: plan the endings before the questions
    
Write your 4 or more endings first, then ask: what does the player need to decide to get to each one? Draw your story map on the handout. If two endings need the exact same answers, they’re really one ending.

  

  
Hint 2: tell the player exactly what to type
    
Put the choices in the prompt, like (yes/no) or (left/right), and compare to those exact lowercase words. Section 05’s “Yes” bug shows what happens when the program and the player disagree.

  

  
Hint 3: build the skeleton first
    
Before writing any endings, write the outer if/else with a placeholder print in each branch, like step 5. Run it both ways. Then fill in one branch at a time.

  

  
Hint 4: where do and, or, not fit?
    
Look at your endings table. Phrases like “has the key and is brave,” “0 books or brave,” and “does not have the map” turn straight into conditions. Make sure each operator ends up on an if line (section 06).

  

  
Hint 5: a question can live inside a branch
    
Not every question has to be asked up front. The exemplar only asks about late books on the right path. Just remember that a variable created inside one branch doesn’t exist on the other path, so only use it there.

  

  
Hint 6: nesting and indentation
    
Each level of nesting adds one more indent. Line up every else exactly under its matching if. If an ending prints at the wrong time, check its indentation first.

  

  
Hint 7: switching drivers
    
A natural place to switch is right after the skeleton works (step 5): one partner builds the questions and skeleton, the other fills in the endings. Both of you should be able to explain every line.
