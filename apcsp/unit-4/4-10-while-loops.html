While Loops

A for loop runs a set number of times. A while loop keeps going as long as a condition is True, which is perfect when you don’t know in advance how many passes it’ll take. How many weeks of saving $25 does it take to reach a goal? Let the loop find out.

01Anatomy of a while loop

  
Example 4.10.3 While Loop Countdown:


i = 10

while i >= 0:
    print(i)
    i -= 1

  
    
    
  1. Python checks the condition. If it’s True, the indented body runs once.
    2. 
    
  2. Then it goes back to the top and checks again.
    3. 
    
  3. The first time the condition is False, the loop ends and the program continues after it.
    4. 
  

  
Unlike for, nothing changes i for you. The body has to do it (i -= 1), or the condition would never change.

02Infinite loops

  
Every working while loop has three parts: set up the variable before the loop, check it in the condition, and change it in the body so the condition eventually becomes False. Break any of them and the loop may never end. That’s an infinite loop; in CodeHS you stop it with the Stop button.

03Looping on user input

  
A while loop can keep asking the user for input until something happens: they run out, they get it right, or they type a special “I’m done” value. Here the user types prices, and the loop stops when they type 0.


total = 0
price = int(input("Price (0 to finish): "))
while price != 0:
    total += price
    print("Running total: " + str(total))
    price = int(input("Price (0 to finish): "))
print("Final total: " + str(total))

  
Notice the input happens in two places: once before the loop, so the condition has something to check, and again at the end of the body, so each pass gets a fresh value. Forget the second one and the loop never sees a new price.

An if inside a while. The body of a loop can hold anything you’ve learned, including if/else. That’s how a program can check each answer (“is this allowed?”) and react differently while the loop keeps going.







  
04while or for?

  
Any for loop can be rewritten as a while loop with a counter. These print the same thing:

  


for lap in range(1, 4):
    print("Lap " + str(lap))


lap = 1                      # set up
while lap <= 3:              # check
    print("Lap " + str(lap))
    lap += 1                 # change

05Remembering two values

  
Some sequences are built from the previous two numbers, so the loop has to remember both and slide them forward each pass. The order of the update lines matters, because each one overwrites a value.

  
Here’s a different sequence that works the same way: the Leonardo numbers, where each new number is the previous two plus 1: 1, 1, 3, 5, 9, 15, 25, … Put the three update lines in an order that works.

  

    
Lab: put the updates in order


first = 1
second = 1
print(first)
while second < 100:
    print(second)

    

    

    

  

  
Why a third variable? Once you change first, its old value is gone. Computing next_num first saves the new value before anything gets overwritten.







  
06On the AP exam

  
The AP reference sheet has no while. It has REPEAT UNTIL, which is the opposite: it repeats until the condition becomes true, which means it keeps going while the condition is false.

  

    
PythonAP pseudocodeKeeps looping while…

    
while x > 0:REPEAT UNTIL (x ≤ 0)x is still positive

    
while guess != secret:REPEAT UNTIL (guess = secret)the guess is wrong

    
while count < 5:REPEAT UNTIL (count ≥ 5)count is under 5

  

  
Flip the condition. To turn a while into REPEAT UNTIL, write the opposite condition (or put NOT in front). Like while, REPEAT UNTIL checks before each pass, so if the condition is already true at the start, the body runs zero times.

Hint 1: the loop condition
    
The program keeps running “while there are still items left.” That phrase is almost your while condition. Start the count at 20 before the loop.

  

  
Hint 2: inside the loop
    
Each pass: show how many are in inventory, ask how many to buy, then use if/else to decide whether the purchase is possible. Only subtract when it is.

  

  
Hint 3: read the sample run closely
    
After the very last purchase, the sample does not print “Now we have 0 left.” It goes straight to “All out!” So the “left” message only prints when there’s still something left. Where does “All out!” go: inside the loop, or after it?

4.10.5 Saving Up

  
Hint 1: set up
    
The instructions remind you to set up a week counter and a total before the loop. Which week does the output start at?

  

  
Hint 2: the condition
    
The loop should run once for each week up to and including the chosen number. Think about < versus <=, and test with 4: you need exactly 4 lines.

  

  
Hint 3: inside the loop
    
Three jobs: add $25 to the total, print the line, move to the next week. Week 1 should already show $25, so think about which job comes first.

  

  
Hint 4: the format
    
Week 1: $25 has no space after the dollar sign. Using commas in print would add spaces (4.9 section 05), so join with + and str().

  


  
4.10.6 Fibonacci

  
Hint 1: two variables
    
You need to remember the last two numbers, and both start at 1. Section 05’s lab uses the same idea with a different rule.

  

  
Hint 2: when to stop
    
The instructions say “up until the max number” but don’t say what it is. The sample ends at 987, and the next Fibonacci number is 1597, so it looks like a max of 1000. A constant like MAX keeps that number in one place.

  

  
Hint 3: checking
    
Your output should start with two 1s and end with 987. If you’re missing the first 1, check what prints before the loop. If you get 1597, your condition checks the wrong number.
