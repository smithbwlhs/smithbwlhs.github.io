01Six comparisons

A comparison asks a yes-or-no question about two values, and the answer is always a Boolean. Python has six of them:

OperatorAsksExampleResult
==equal to?4 == 4True
!=not equal to?4 != 4False
>greater than?18 > 17True
<less than?18 < 17False
>=greater than or equal to? (“at least”)25 >= 25True
<=less than or equal to? (“at most”)26 <= 25False

= stores, == asks. One equals sign puts a value into a variable. Two equals signs compare. roll1 = roll2 copies a value; roll1 == roll2 asks whether they match. For the two-character operators, the = always goes second: >=, never =>.

02Comparing what the user types

Example 4.3.3 Voting Age puts it together in three lines:

age = int(input("What is your age? "))
old_enough = age > 17
print("Can vote: " + str(old_enough))
  1. int(input(...)) reads text and turns it into a whole number (you did this in Unit 3).
  2. age > 17 compares, and the Boolean answer is stored in old_enough.
  3. The result is printed with a label, using str() like in 4.1 and 4.2.

Notice that age > 17 and age >= 18 give the same answer for every whole number. When you read a rule like “18 or older,” either works. >= 18 usually matches the wording better.

03Ranges & boundaries

To check that a number is between two values, you need two comparisons joined with and. That’s example 4.3.4 Grade Range:

grade = int(input("What is your grade? "))
got_b = grade >= 80 and grade < 90
print("Got a B: " + str(got_b))
# always test values at the boundaries

That last comment is the most important line in the example. A boundary is where the answer flips from False to True. Bugs hide there: one wrong > instead of >= changes exactly one value. Here that’s the difference between a student with an 80 getting a B or not.

Each side of and needs its own complete comparison. In English you can say “at least 80 and below 90.” In Python, grade >= 80 and < 90 is a syntax error. Write the variable again: grade >= 80 and grade < 90.

Python also allows a shortcut, 80 <= grade < 90, which the number line understands. The CodeHS examples and the AP exam use the and form, so that’s the one to practice.

04The input() trap

input() always gives you a string, even when the user types digits. Strings compare differently from numbers. == checks if the text matches exactly, and < / > compare letter by letter like a dictionary. That’s why every CodeHS example wraps input() in int() before comparing.

Lab: text vs. numbers

Pretend the user typed these two answers. Spaces count.

Comparing a string to a number crashes. If you forget int() and write age > 17, Python stops with TypeError: '>' not supported between instances of 'str' and 'int'. == doesn’t crash, but "4" == 4 is always False, which is harder to notice.

05Comparisons + and / or

Comparisons produce Booleans, so you can feed them straight into the logical operators from 4.2. Python does all the comparisons first, then not, then and, then or. Parentheses still go first of all.

Here’s a theme-park rule: you can ride if you’re at least 48 inches tall, or if you’re at least 42 inches and riding with an adult.

can_ride = height >= 48 or (height >= 42 and with_adult)

The parentheses aren’t required here, because and already goes before or, but they make the two ways to qualify easy to see. Put numbers into expressions like this in the lab and step through them.

06On the AP exam

  
The AP reference sheet calls these relational operators. Most of them are written with math symbols instead of two characters.

  

    
IdeaPythonAP pseudocode

    
Equal toa == ba = b

    
Not equal toa != ba ≠ b

    
Greater / less thana > b, a < ba > b, a < b

    
At least / at mosta >= b, a <= ba ≥ b, a ≤ b

    
Store a valuea = 5a ← 5

  

  
A single = means different things. On the AP exam, = compares, because storing uses the arrow ←. In Python, = stores and == compares. When you read an exam question, a = b is a question with a true/false answer.
