01Programs that wait

An event is something that happens while a program is running, like a key press or a mouse click. An event-driven program works in two parts:

  1. Setup runs once, top to bottom, when you press Run: make the shapes, add them to the canvas, and tell Python which code to run when a key is pressed.
  2. The handler runs again every time a key is pressed. It’s the code inside def key_down(event):.

Example 4.6.3 Keyboard Square shows both parts. Click the canvas and press the arrow keys (or use the buttons). Watch which lines run for each key.

Lab: run 4.6.3 Keyboard Square

  

  
New syntax: def. def key_down(event): creates a named block of code, called a function, that doesn’t run right away. It waits until something calls it. You’ll learn to write your own functions in Unit 5; for now, the pattern is all you need. The indented lines belong to the function, just like an if body.

  
No parentheses when you hand it over. add_key_down_handler(key_down) gives Python the name of your function so it can call it later. Writing key_down() there would try to run it immediately, before any key has been pressed.







  
02Which key was it?

  
When Python calls your handler, it passes in event, which holds information about what just happened. event.key is a string naming the key. That’s why the handler uses if event.key == "ArrowLeft":, a string comparison like the ones in 4.4.

The name must match exactly. It’s "ArrowLeft": capital A, capital L, no space. "arrowleft", "Left", and "Arrow Left" are all different strings, so the if would never be True. Letters are case-sensitive too: holding Shift turns "a" into "A".

  
The example uses four separate if statements. A single key press can only match one of them, so if/elif from lesson 4.5 would behave the same here. Either is fine.







  
03Moving on the canvas

  
square.move(dx, dy) moves a shape relative to where it is now: dx is the change in x and dy is the change in y. The surprise is the y direction: on a computer canvas, (0, 0) is the top-left corner and y gets bigger going down. That’s why “up” is move(0, -5).

04Read, change, write

  
move() changes a position for you. To change something like a circle’s size, you do it in three steps:

  
    
    
  1. Read the current value with a get_ method, like get_radius().
    2. 
    
  2. Change it with math: add or subtract.
    3. 
    
  3. Write the new value back with the matching set_ method, like set_radius(new_radius).
    4. 
  

  
It’s the same idea as score = score + 10: you can’t add to a value until you know what it is. Try it on a circle. The log shows each step.

05Setting limits

06On the AP exam

  
The AP pseudocode has no key events, so you won’t trace add_key_down_handler on the exam. The idea is part of the course, though: AP CSP describes event-driven programming, where some code runs when it’s triggered by an event such as a key press, a click, or a timer, rather than straight through from top to bottom.

  

    
Sequential programEvent-driven program

    
Runs top to bottom, then endsRuns its setup, then waits

    
The program decides what happens nextThe user’s actions decide what happens next
